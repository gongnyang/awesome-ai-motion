01

무엇을 전하나What it tells

전달 효과ConveysCONVEYS
스크롤과 설명 진행이 직접 연결되어 보는 사람이 속도를 쥔다. 되감기가 자유롭다Scroll and explanation progress are tied directly, so the viewer holds the pace and can rewind freely.
언제 쓰나Use whenUSE WHEN
  • 단계별 설명을 스크롤 길이에 묶어 원하는 속도로 읽게 할 때
  • 제품 회전이나 도해를 스크롤로 되감아 보게 할 때
  • Bind step-by-step explanation to scroll length so people read at their own speed.
  • Let viewers scrub a product rotation or diagram back and forth.
과용 주의AvoidAVOID
  • scrub 중에는 스프링 이징 금지(ease-out 또는 linear)
  • 자동 재생과 scrub을 한 요소에 섞지 않는다

02

좋은 예와 나쁜 예Good and bad use

좋은 사례GOOD

스크롤 1200px 구간이 타임라인 progress 0~1에 대응하고 화면은 500ms 지연으로 부드럽게 따라온다

과용 · 나쁜 사례OVERUSE

progress와 스크롤을 연결하지 않고 스크롤이 시작되면 자동 재생돼 되감기가 안 된다. 스크롤 구간이 300px라 너무 민감하다

// ScrollTrigger 없이 코어만: 스크롤 값을 progress로 변환
let target = 0, cur = 0;
addEventListener('scroll', () => target = Math.min(1, scrollY / 1200));
gsap.ticker.add(() => { cur += (target - cur) * 0.12; tl.progress(cur); });

에이전트 프롬프트Agent prompts

그대로 붙여 넣는다Paste as is

Claude Code

<대상> 타임라인을 스크롤로 스크럽하게 해줘. 스크롤 0~1200px를 progress 0~1에 대응시키고 GSAP ticker에서 cur += (target - cur) * 0.12로 부드럽게 따라가게 해. 타임라인은 paused이고 자동 재생은 없어야 해.

Make the timeline in <target> scrub with scroll. Map scroll 0 to 1200px to progress 0 to 1, and follow smoothly in the GSAP ticker with cur += (target - cur) * 0.12. The timeline is paused with no autoplay.

Codex

<파일>에 scroll scrub를 구현해. 스크롤 구간 1200px, 지연 계수 0.12, tl.progress(cur)만 호출한다. scrollY 0, 300, 600, 1200 시점에 캡처해 progress가 0, 0.25, 0.5, 1이고 되감을 때 같은 프레임이 나오는지 확인해.

Implement scroll scrub in <file>: 1200px scroll range, smoothing 0.12, only tl.progress(cur) is called. Capture at scrollY 0, 300, 600 and 1200 and verify progress is 0, 0.25, 0.5 and 1, and that rewinding yields identical frames.

05

도구별로 쓰기In your tools

HyperFrames · ReelForge · Scrolline

HyperFramesVIDEO · GSAP
HyperFrames는 스크롤이 없으므로 progress를 시간축으로 고정해 렌더한다. scrub 로직은 웹 프리뷰용이고 렌더 결과는 같은 tl이다
ReelForgeBRIEF TO VIDEO
ReelForge는 시간 기반이므로 scrub을 쓰지 않는다. 대신 각 씬의 progress 구간 정의를 파라미터로 노출한다
Scrolline DeckSCROLL SCRUB
Scrolline의 기본 방식이다. 스크롤 구간을 progress 0..1로 정규화하고 스프링 대신 ease-out과 500ms 지연을 쓴다
