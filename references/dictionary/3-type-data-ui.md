# 3 타이포와 데이터 애니메이션

조사·확인일: 2026-09-30. 담당: M3. 용도: 3~5분 설명 영상, 스크롤덱, 체험관. 밝은 편집 디자인에서 입력 행동·데이터 변화·LLM 원리를 읽히게 만드는 동작 설계 사전.

## 적용 기준

시간·이동량·간격은 별도 표시가 없으면 우리 교재의 시작값 제안. 공식 가이드의 보편적 강제 규격이나 실측 결과가 아님. 실제 발화 길이·한글 줄바꿈·최종 해상도에 맞춰 조정. 1920×1080 영상 기준 px, 화면이 작으면 비례 축소보다 가독성 우선. 핵심 문장과 데이터는 움직임이 끝난 뒤 정지 화면으로도 뜻이 완성되게 구성.

타이포는 내레이션에서 해당 낱말을 말하는 순간에 맞춤. 본문·상시 자막은 안정적으로 읽히게 유지하고, 키네틱 타이포는 제목·핵심어·짧은 대비 문장에 사용. 밝은 바탕에는 먹색 본문, 한 가지 강조색, 옅은 보조선 사용. 일반 텍스트 대비 4.5:1, 큰 텍스트 3:1을 출발 기준으로 삼음. 색 변화만으로 선택·증감을 전달하지 말고 라벨·기호 병용.

실제 녹화 / 실제 응답 재현 / 가상 예시 / API 실행을 화면과 기록에서 구분. 아래 입력·스트리밍 시간은 연출값이며 실제 서비스 속도나 토큰 생성 속도의 증거가 아님. 긴 프롬프트는 핵심 조건만 2~4초 타이핑하고 나머지는 붙여 넣기. 어텐션 가중치·확률·임베딩 좌표가 예시라면 화면에 `설명용 예시` 표시.

### 이징 공통 키

| 키 | 곡선 이름과 CSS 값 | GSAP 적용 | 용도 |
| :--- | :--- | :--- | :--- |
| L | 선형 · Linear, `cubic-bezier(0,0,1,1)` | `none` | 값·거리·진행률의 일정한 변화 |
| E | Material legacy decelerate, `cubic-bezier(0,0,0.2,1)` | `CustomEase`로 동일 곡선 등록 | 제목·주석 진입 |
| S | Material legacy standard, `cubic-bezier(0.4,0,0.2,1)` | `CustomEase`로 동일 곡선 등록 | 위치 변경·확대·상태 보간 |
| P | Carbon productive standard, `cubic-bezier(0.2,0,0.38,0.9)` | `CustomEase`로 동일 곡선 등록 | 조용한 UI·데이터 변화 |
| PE | Carbon productive entrance, `cubic-bezier(0,0,0.38,0.9)` | `CustomEase`로 동일 곡선 등록 | UI 피드백 등장 |
| X | Material legacy accelerate, `cubic-bezier(0.4,0,1,1)` | `CustomEase`로 동일 곡선 등록 | 퇴장 |
| Q | 불연속 · Discrete, `steps(N,end)` | `steps(N)` 또는 시간 임계값 조회 | 글자·청크·격자 단위 공개 |

E·S·X는 Material 3의 새 standard 계열과 다른 legacy 곡선. Material 3 공식 토큰은 standard `(0.2,0,0,1)`, standard decelerate `(0,0,0,1)`, standard accelerate `(0.3,0,1,1)`도 제공. 프로젝트에서 계열 하나를 골라 명시. `power3.out`은 로컬 HyperFrames의 진입 기본값이지만 E와 정확히 같은 곡선이 아님. Q는 계단 함수라 대응하는 단일 cubic-bezier 없음. 수치형 데이터에는 overshoot·bounce·elastic 금지: 중간 프레임이 실제 범위를 넘거나 잘못된 수치로 보이기 때문. [S1][S2][S4]

### 런타임 공통 계약

GSAP 시간 단위는 초. 문서의 ms를 1000으로 나눠 `duration`·`stagger`·위치에 입력. HyperFrames에서는 장면 합성 타임라인 하나를 `paused:true`로 만들고 `window.__timelines`에 등록. 아래 방식은 그 타임라인에 동작을 추가하는 레시피. `.clip` 생명주기는 HyperFrames에 맡기고 내부 래퍼를 움직임.

초기값과 최종값을 `fromTo`로 명시. 같은 속성을 다시 소유하는 후속 tween에는 필요에 따라 `immediateRender:false` 사용. 위치는 `x/y/scale/rotation`, 막대는 `scaleX/scaleY`. `width/height/top/left` 애니메이션으로 레이아웃을 흔들지 않음. 폰트·줄바꿈·좌표·SVG 길이는 구성 준비 단계에서 확정. 렌더 중 DOM 측정·네트워크 요청·시계·난수·무한 반복 금지. 스크램블·캐럿·타이핑도 현재 시간의 순수 함수로 계산.

CSS `transition`은 영상 애니메이션 대상에 사용 금지. 영상용 CSS keyframes는 HyperFrames 어댑터로 현재 시간에 묶어 seek 가능하게 사용. D3는 좌표·경로·보간 함수 계산에 사용하고 자율 재생 `d3.transition()`은 HyperFrames 안에서 별도 실행하지 않음. 웹 체험관은 실제 사용자 이벤트에 반응하되 취소·중복 클릭·재실행 상태 정의. [L1][L2][S6]

스크롤덱은 초 대신 장면 진행률 `p∈[0,1]` 사용. Scrolline 로컬 계약은 진입 0~0.30, 읽기 홀드 0.30~0.75, 퇴장 0.75~1.00, 기본 `scrub:0.6`. `pinVh`는 스크롤 거리이지 재생시간이 아님. 다음 항목의 ms를 그대로 0~1 타임라인에 넣지 말고 구간 길이로 다시 설계. 35% 키보드 착지와 55% 캡처에서 핵심 내용이 읽혀야 함. 중간 과정이 긴 원리 설명은 여러 장면으로 분리. 모션 축소에서는 핀·줌·큰 이동 제거, 최종 상태와 단계 버튼·정적 주석 제공. [L3][S3][S5]

## A. 키네틱 타이포

### 01. 타자기 · Typewriter

**한 줄 정의**: 글자를 하나씩 불연속으로 공개하는 텍스트 연출.

**무엇을 전달하나**: 입력·작성의 진행과 문장 형성 순서.

**우리 교재에서 쓸 장면 예**: “대상: 신입 직원”을 프롬프트 제목으로 입력.

**기본 파라미터**: 40~70ms/글자, 어절 쉼 150~250ms, 완료 홀드 1000~1600ms; Q, 글자 사이 이동 0px.

**구현 메모**: Intl.Segmenter의 grapheme 배열을 준비하고 현재 시간으로 공개 개수 계산. 최종 크기 상자·줄바꿈을 미리 고정. [S7].

**과용 주의·금지**: UTF-16 코드 단위 slice로 이모지·결합 문자를 깨지 않게 함. 본문 전체를 타자기로 지연시키지 않음.


### 02. 글자별 스태거 · Per-character stagger

**한 줄 정의**: 글자마다 짧은 시차를 줘 진입시키는 방식.

**무엇을 전달하나**: 하나의 제목 안에서 읽기 방향과 리듬.

**우리 교재에서 쓸 장면 예**: “답은 예측으로 만들어진다” 제목 등장.

**기본 파라미터**: 글자당 240~360ms, 시작 간격 20~35ms, 총 시차 ≤500ms; E, y 8~16px.

**구현 메모**: grapheme별 inline-block, opacity 0→1·y→0을 동일 tl.fromTo에 stagger. 전체 문장 접근성 이름을 남기고 조각은 aria-hidden. [S4].

**과용 주의·금지**: 자모 분리 금지. 긴 제목은 글자 대신 어절로 분할. 글자마다 회전·바운스 금지.


### 03. 단어 강조 · Word emphasis

**한 줄 정의**: 이미 읽히는 문장에서 특정 단어의 대비를 잠깐 높이는 방식.

**무엇을 전달하나**: 핵심 조건·부정·주의의 우선순위.

**우리 교재에서 쓸 장면 예**: “출처를 확인해”에서 “출처” 강조.

**기본 파라미터**: 진입 150~220ms, 유지 800~1400ms, 복귀 180ms; PE, scale 1→1.03 이하, 강조 간격 ≥600ms.

**구현 메모**: 단어 배경판 opacity나 색을 발화 라벨에 연결. 본문은 이동 없이 유지. scale은 별도 래퍼에 적용.

**과용 주의·금지**: 한 문장에 1~2개만 강조. 부정어를 빼고 명사만 강조해 뜻을 뒤집지 않음.


### 04. 스크램블 · Text scramble / Decode

**한 줄 정의**: 가짜 문자 상태를 거쳐 최종 문자를 확정하는 연출.

**무엇을 전달하나**: 불확실한 상태에서 확정된 표기로 전환.

**우리 교재에서 쓸 장면 예**: 짧은 전환 타이틀 “검증 완료” 공개.

**기본 파라미터**: 총 350~600ms, 교체 간격 50~80ms, 확정 홀드 ≥1200ms; L 드라이버+Q, 글자 이동 0px.

**구현 메모**: 문자·시간 구간 인덱스를 고정 해시로 매핑. 매번 현재 시간에서 전체 문자열 재구성. 최종 문자열·폭을 고정.

**과용 주의·금지**: AI가 실제로 암호를 해독한다는 암시 금지. 수치·핵심 정의·자막에는 사용 금지. Math.random 금지.


### 05. 마스크 텍스트 · Masked text reveal

**한 줄 정의**: 고정된 잘림 영역 안에서 글자나 행을 드러내는 방식.

**무엇을 전달하나**: 정보의 단계 공개와 깔끔한 제목 진입.

**우리 교재에서 쓸 장면 예**: “입력 → 연결 → 다음 토큰”을 행별 공개.

**기본 파라미터**: 행당 350~500ms, 행 시차 80~120ms; E, y 0.8~1행 높이, 행 간격 12~20px.

**구현 메모**: overflow:hidden 행 래퍼 안 텍스트 y를 최종 0으로 이동. SplitText mask 지원 또는 고정 행 DOM 사용. [S4].

**과용 주의·금지**: 한글 윗부분·밑줄 잘림 방지 여백 확보. 읽는 중인 행을 다시 가리지 않음.


### 06. 하이라이트 스윕 · Highlight sweep

**한 줄 정의**: 형광펜 같은 면이 글자 뒤로 지나가며 남는 강조.

**무엇을 전달하나**: 읽어야 할 범위와 조건의 경계.

**우리 교재에서 쓸 장면 예**: “첨부 자료만 근거로 답해” 조건 구간 표시.

**기본 파라미터**: 350~550ms, 유지 1200~2000ms, 다음 강조 간격 ≥500ms; E, 배경판 scaleX 0→1, 상하 여백 4~6px.

**구현 메모**: 본문 뒤 배경판에 transform-origin:left. 한 줄 넘는 범위는 행별 판으로 쪼갬.

**과용 주의·금지**: 반짝이는 gradient shimmer와 구분. 밝은 강조색으로 글자 대비를 떨어뜨리지 않음. 모든 문장 칠하기 금지.


### 07. 밑줄 드로우 · Underline draw

**한 줄 정의**: 선이 한쪽 끝에서 다른 끝으로 그려지는 강조.

**무엇을 전달하나**: 특정 단어·결론의 위치 고정.

**우리 교재에서 쓸 장면 예**: “사실 확인은 별도” 결론 아래 선 긋기.

**기본 파라미터**: 250~400ms, 유지 ≥1500ms, 동시 선 1개; E, 두께 2~4px, 글자와 간격 5~8px.

**구현 메모**: 직선은 scaleX, 곡선은 SVG dashoffset. 선과 텍스트 별도 레이어 유지.

**과용 주의·금지**: 가독성을 해치는 글자 관통 금지. 링크처럼 보이는 파란 밑줄은 체험관 실제 링크와 구분.


### 08. 카운트업 · Count-up

**한 줄 정의**: 시작값에서 목표 숫자까지 표시값을 증가시키는 연출.

**무엇을 전달하나**: 규모·누적·최종 수치에 주목.

**우리 교재에서 쓸 장면 예**: 예시 컨텍스트 사용량 0→2400토큰.

**기본 파라미터**: 600~1000ms, 완료 홀드 ≥1200ms, 숫자 갱신 33~50ms 또는 렌더 프레임; L 또는 P, 이동 0px.

**구현 메모**: 숫자 proxy를 tween하고 Intl.NumberFormat·tabular-nums로 표시. 마지막 값은 원자료에서 고정하고 매 시점 재계산.

**과용 주의·금지**: 날짜·전화번호·식별자에는 사용 금지. 감소값은 count-down. 소수 반올림·단위·분모를 고정.


### 09. 단어 릴레이 · Word relay

**한 줄 정의**: 짧은 어구가 순서대로 초점을 넘기는 제목 구성.

**무엇을 전달하나**: 절차·대비의 한 단계씩 읽기.

**우리 교재에서 쓸 장면 예**: “자료 넣기 → 조건 쓰기 → 답 검토”.

**기본 파라미터**: 어구당 350ms 진입+900~1400ms 홀드, 시차 1200~1800ms; E/X, x 24~48px.

**구현 메모**: 2~5개 어구를 고정 무대에 배치하고 이전·다음의 가시 구간을 tl에 선언. Scrolline word-relay는 진행률로 적용. [L3].

**과용 주의·금지**: 설명을 시작하기 전에 전부 사라지지 않게 최종 요약 남김. 긴 문장 연쇄·빠른 단어 교체 금지.


### 10. 발화 동기 강조 · Speech-synchronized emphasis

**한 줄 정의**: 발화 시각에 맞춰 현재 어구를 강조하는 방식.

**무엇을 전달하나**: 듣는 내용과 보는 위치의 대응.

**우리 교재에서 쓸 장면 예**: 컨텍스트 정의를 읽는 순간 “지금 제공된 정보” 강조.

**기본 파라미터**: 발화 시작±0~100ms, 진입 100~150ms, 어구 간격은 실제 타임스탬프; PE, 이동 0px.

**구현 메모**: 검수한 단어·어구 start/end 배열에서 opacity·배경 강조 계산. 한국어 뜻 단위 수동 묶음 사용. [L2].

**과용 주의·금지**: ASR 오류 시 자동 그대로 쓰지 않음. 자막 전체가 튀거나 매 음절 점프하는 연출 금지.


## B. 데이터 시각화 애니메이션

### 11. 막대 성장 · Bar growth

**한 줄 정의**: 같은 기준선에서 막대 길이가 목표값까지 자라는 동작.

**무엇을 전달하나**: 양의 크기와 항목 간 비교.

**우리 교재에서 쓸 장면 예**: 세 가지 프롬프트의 검토 시간 예시 비교.

**기본 파라미터**: 500~800ms, 항목 간격 50~90ms, 전체 시차 ≤400ms; L 또는 P, 막대 간격 16~24px.

**구현 메모**: 최종 크기 막대에 scaleY·origin:bottom 또는 scaleX·origin:left. 축·단위·라벨은 먼저 정적으로 표시. [L1].

**과용 주의·금지**: 막대 baseline 0 고정. 양·음 값은 0선에서 반대 방향으로 성장. 데이터가 큰 항목만 늦게 끝나면 읽기 순서 왜곡 주의.


### 12. 선 그리기 · Path draw / Stroke reveal

**한 줄 정의**: 경로의 선분을 순서대로 드러내는 방식.

**무엇을 전달하나**: 흐름·연결·시간 순서.

**우리 교재에서 쓸 장면 예**: 입력 문장에서 다음 토큰까지 이어지는 경로.

**기본 파라미터**: 700~1200ms, 경로 시차 100~180ms; L, 선 2~4px, 주석 등장은 완료 후 150ms.

**구현 메모**: SVG stroke-dasharray와 stroke-dashoffset. 길이는 준비 때 getTotalLength로 확정. 덱 규약은 pathLength=1로 정규화. [L1][L3].

**과용 주의·금지**: 차트 path 길이 일정 공개는 x축 시간 일정 공개와 다름. 실제 시간 경과를 뜻할 때는 x축 clip을 사용. 선을 데이터 증가로 오인시키지 않음.


### 13. 점 이동 트랜지션 · Point transition / Object constancy

**한 줄 정의**: 같은 데이터 객체를 유지하며 좌표만 이동시키는 동작.

**무엇을 전달하나**: 변화 전후 같은 대상의 추적.

**우리 교재에서 쓸 장면 예**: 질문이 바뀔 때 같은 문서 점들의 관련도 위치 변화.

**기본 파라미터**: 600~1000ms, 동시 시작 또는 그룹 시차 40~70ms; S/P, 점 반경 5~8px, 라벨 간격 ≥12px.

**구현 메모**: id로 전후 좌표 매핑. D3 scale로 좌표를 계산하고 GSAP x/y 또는 순수 보간으로 이동. [S6].

**과용 주의·금지**: 점이 새 객체로 바뀌는데 같은 id를 붙이지 않음. 중간 위치는 관측값이 아닌 전환임을 구분. 군집 교차 시 선택 점 외 라벨 절제.


### 14. 모프·보간 · Morphing / Interpolation

**한 줄 정의**: 두 상태 사이의 수치·형상을 연속적으로 계산하는 방식.

**무엇을 전달하나**: 구조의 대응과 변환 관계.

**우리 교재에서 쓸 장면 예**: 입력 조건 추가 전후의 확률 분포 변화.

**기본 파라미터**: 600~900ms, 단계 홀드 1200~1800ms; S 또는 L, 대응 요소 간격 고정.

**구현 메모**: 숫자·색·좌표를 interpolate. SVG 형상은 대응 점·경로 구조를 정규화하거나 MorphSVG 준비 여부 확인. [S6].

**과용 주의·금지**: 문자열 d 속성 단순 숫자 보간만으로 임의 경로 모프 금지. 무관한 차트 유형을 모프해 동일 데이터를 암시하지 않음.


### 15. 단위 격자 채우기 · Unit grid / Waffle fill

**한 줄 정의**: 동일 면적의 칸을 일정 단위만큼 채우는 방식.

**무엇을 전달하나**: 비율·분모·한 단위의 의미.

**우리 교재에서 쓸 장면 예**: 100칸 중 설명용 35칸을 참고 정보로 채우기.

**기본 파라미터**: 칸당 80~120ms, 시작 간격 10~20ms, 전체 700~1200ms; Q 또는 PE, 칸 간격 4~8px.

**구현 메모**: 총 칸 수·채움 순서·각 칸 값 고정. scale이나 opacity로 채움. 큰 배열은 그룹 단위 공개.

**과용 주의·금지**: 격자 비율과 원값이 다른 반올림은 표기. 서로 다른 분모를 같은 100칸처럼 비교하지 않음. 색 외 범례 병용.


### 16. 줌 인셋 · Zoom inset / Detail view

**한 줄 정의**: 전체 맥락을 남긴 채 일부 영역을 별도 창에 확대.

**무엇을 전달하나**: 미세한 차이와 전체 속 위치.

**우리 교재에서 쓸 장면 예**: 확률 막대의 상위 두 후보 차이 확대.

**기본 파라미터**: 확대 450~650ms, 홀드 1600~2400ms; S, 확대 1.8~3배, 원본·인셋 간격 32~48px.

**구현 메모**: 선택 영역 테두리·연결선을 먼저 표시하고 복제 래퍼 scale·opacity로 등장. 원본과 인셋 데이터 동일.

**과용 주의·금지**: 확대 축 범위를 표시. 전체와 확대에서 비율이 다르면 명시. 확대가 새 데이터처럼 보이거나 본문을 덮지 않음.


### 17. 주석 등장 · Annotation reveal

**한 줄 정의**: 데이터의 특정 위치에 설명·화살표를 순차 공개.

**무엇을 전달하나**: 왜 보아야 하는지와 해석의 단서.

**우리 교재에서 쓸 장면 예**: 다음 토큰 후보 중 “가장 높아도 정답 보장은 아님” 주석.

**기본 파라미터**: 선 250~350ms, 텍스트 180~250ms, 후행 100~150ms, 홀드 ≥1800ms; E, 주석·점 간격 16~24px.

**구현 메모**: 앵커 좌표 고정 후 선 draw→라벨 fade. 선택 점과 주석 묶음을 동일 상태로 관리.

**과용 주의·금지**: 한 화면 1~3개. 실제 통계 근거 없는 인과 주석 금지. 주석이 축·수치·자막을 가리지 않음.


### 18. 스크롤리텔링 단계 · Scrollytelling steps

**한 줄 정의**: 스크롤 구간별 데이터 상태와 설명을 연결.

**무엇을 전달하나**: 독자 속도로 단계적 이해.

**우리 교재에서 쓸 장면 예**: 질문→토큰→어텐션→확률의 4단계 원리 덱.

**기본 파라미터**: 영상 환산 단계당 800ms 변화+1800ms 홀드; S, 웹 p 구간·pinVh 220~300 시작값, scrub 600ms.

**구현 메모**: paused tl을 ScrollTrigger 진행률에 연결. Scrolline은 장면당 길이 1 계약 준수. 단계 버튼·키보드·정적 fallback 제공. [S5][L3].

**과용 주의·금지**: 스크롤 속도로 읽을 시간이 보장된다고 가정하지 않음. 강제 핀·snap으로 되돌아보기 막지 않음. 실제 이벤트 기록과 재생 연출 분리.


### 19. 순위 재배치 · Rank transition

**한 줄 정의**: 값 변화에 따라 같은 항목의 표시 순서를 이동.

**무엇을 전달하나**: 순위 변동과 항목 정체성.

**우리 교재에서 쓸 장면 예**: 질문 조건 수정 전후 검색 문서 순위 비교.

**기본 파라미터**: 500~800ms, 변경 후 홀드 ≥1600ms; P, 행 높이 48~64px, 시차 0~40ms.

**구현 메모**: 고정 id와 전후 rank 좌표를 준비. 라벨과 막대 래퍼를 함께 x/y 이동하고 수치는 동일 시점 갱신.

**과용 주의·금지**: 읽는 중 지속 정렬 금지. 동점 정책·정렬 기준 명시. 랭킹 변화가 실제 성능 우열이라는 암시 금지.


### 20. 누적 채우기 · Cumulative fill / Progress fill

**한 줄 정의**: 정해진 전체에서 사용·완료된 양을 채우는 동작.

**무엇을 전달하나**: 부분과 전체·한계까지 남은 양.

**우리 교재에서 쓸 장면 예**: 파일 업로드 단계 또는 컨텍스트 사용량.

**기본 파라미터**: 350~600ms/변경, 단계 사이 ≥700ms; L/P, 진행 막대 높이 12~20px.

**구현 메모**: 최종 폭 래퍼 scaleX=사용량/전체. 텍스트 분자·분모를 같은 driver로 계산.

**과용 주의·금지**: 작업 완료율을 모르면 indeterminate로 구분. 모르는 대기 시간을 가짜 99%로 표현 금지. 연출 진행과 실제 처리 분리.


## C. UI 시연

### 21. 커서 이동 · Cursor movement

**한 줄 정의**: 포인터가 조작할 목표까지 이동하는 시연 동작.

**무엇을 전달하나**: 다음 행동의 위치와 조작 순서.

**우리 교재에서 쓸 장면 예**: 첨부 버튼→파일 선택→입력창 이동.

**기본 파라미터**: 이동 350~600ms, 목표 도착 후 120~200ms 쉼; S, 목표 중앙 또는 실제 클릭 지점, 커서 주변 여백 ≥16px.

**구현 메모**: 고정 좌표 사이 x/y tween. 짧은 아크는 사전 경로를 사용. 실제 녹화 커서가 있으면 별도 커서 중복 표시 방지.

**과용 주의·금지**: 불필요한 배회·빠른 왕복 금지. 가상 커서가 실제 클릭 증거처럼 보이지 않게 재현 표기.


### 22. 클릭 리플 · Click ripple

**한 줄 정의**: 클릭 위치에서 짧게 퍼지는 원형 피드백.

**무엇을 전달하나**: 어디를 눌렀는지와 입력 접수.

**우리 교재에서 쓸 장면 예**: 전송 버튼 클릭 순간 표시.

**기본 파라미터**: 250~400ms, 후속 UI 반응 0~150ms 뒤; PE, 원 반경 12→28px, 최대 opacity 0.25.

**구현 메모**: 절대 좌표 원 래퍼 scale·opacity를 같은 클릭 라벨에서 tween. 클릭 대상 상태 변화와 연결.

**과용 주의·금지**: 화면 전체 섬광·큰 파동 금지. 클릭 접수와 작업 완료 혼동 금지. 실제 UI에 없는 기능처럼 꾸미지 않음.


### 23. 타이핑 입력 · Typing input simulation

**한 줄 정의**: 입력창에 키 입력·쉼·붙여 넣기 상태를 재현.

**무엇을 전달하나**: 어떤 조건을 어떻게 작성하는지.

**우리 교재에서 쓸 장면 예**: 역할·대상·출력 형식을 짧게 입력.

**기본 파라미터**: 60~120ms/완성 글자, 구간 쉼 250~400ms, 핵심 입력 전체 2000~4000ms; Q, 캐럿 주기 800~1000ms.

**구현 메모**: [{t,text}] 전체 상태 배열로 현재 문자열 조회. 실제 한국어 IME가 필요하면 자모 조합 상태까지 따로 기록. [L1][S7].

**과용 주의·금지**: 타자기 제목과 달리 포커스·캐럿·전송 가능 상태도 맞춤. 불필요한 오타 연출 금지. grapheme을 모델 토큰으로 부르지 않음.


### 24. 답 스트리밍 · Answer streaming

**한 줄 정의**: 응답 문장이 여러 청크로 점진적으로 표시되는 연출.

**무엇을 전달하나**: 응답 생성 중 상태와 완료의 구분.

**우리 교재에서 쓸 장면 예**: 저장한 실제 응답의 핵심 문단 재현.

**기본 파라미터**: 청크 간 50~140ms, 문단 쉼 200~400ms, 핵심 답 2000~5000ms; Q, 줄 간격 1.45~1.6.

**구현 메모**: 청크 시각·문자열·줄배치를 미리 고정. 현재 시간 이하 청크를 합쳐 표시하고 마지막에 완료 상태. [L2].

**과용 주의·금지**: UI 청크는 모델 토큰과 일대일이 아님. 실제 속도 비교에 연출값 사용 금지. 덜 완성된 문장을 먼저 결론으로 강조하지 않음.


### 25. 화면 스크롤 · UI scroll demonstration

**한 줄 정의**: 콘텐츠 뷰포트 안에서 문서가 이동하는 시연.

**무엇을 전달하나**: 화면 아래 정보와 문서의 연속성.

**우리 교재에서 쓸 장면 예**: 응답 아래 비교표로 내려가기.

**기본 파라미터**: 500~900ms, 도착 후 홀드 ≥1600ms; S, 이동 0.5~1화면 높이, 상하 안전 여백 48~72px.

**구현 메모**: 합성 영상은 overflow:hidden 안 콘텐츠 y를 절대 좌표로 이동. 웹 실제 스크롤은 사용자 이벤트와 단계 컨트롤 유지.

**과용 주의·금지**: Scrolline 프로젝트는 scrollTo·scrollIntoView 금지 계약 준수. 긴 자동 스크롤·읽는 동안 계속 이동 금지. 도착점 제목 남김.


### 26. 확대 콜아웃 · Magnified callout / UI focus zoom

**한 줄 정의**: 특정 UI 영역을 확대하고 바깥 맥락을 낮추는 연출.

**무엇을 전달하나**: 클릭 목표·응답 차이의 가독성.

**우리 교재에서 쓸 장면 예**: 첨부 파일 이름과 출처 버튼 확대.

**기본 파라미터**: 450~650ms 확대, 홀드 1800~2500ms, 복귀 400ms; S, scale 1.4~2.2, 목표·자막 간격 ≥48px.

**구현 메모**: 내부 화면 래퍼에 transform-origin과 x/y/scale. 작은 콜아웃은 영역 복제·연결선 방식. 실제 클릭 좌표는 원본과 동기화.

**과용 주의·금지**: 확대로 주변 메뉴 맥락을 잃지 않게 안내. 흐린 원본을 과도하게 키우지 않음. 확대 중 커서 목표 불일치 금지.


### 27. 포커스·선택·피드백 · Focus / Selection / Feedback

**한 줄 정의**: 행동할 대상과 선택 결과를 시각 상태로 구분.

**무엇을 전달하나**: 입력 준비·선택·확정 상태의 차이.

**우리 교재에서 쓸 장면 예**: 입력창 포커스→문서 선택→첨부 완료 칩.

**기본 파라미터**: 포커스 100~150ms, 선택 150~200ms, 완료 200~300ms; PE/P, 테두리 2~3px, 상태 간격 ≥150ms.

**구현 메모**: 체험관 실제 focus-visible·aria-selected·disabled 상태를 기준으로 스타일. 영상은 동일 상태표를 시간에 매핑.

**과용 주의·금지**: hover를 클릭 완료로 오인시키지 않음. 키보드 포커스 테두리 제거 금지. 실제 반응을 연출 지연으로 막지 않음.


## D. 우리 원리 도해

### 28. 토큰 쪼개기 · Tokenization split

**한 줄 정의**: 문자열을 토크나이저 결과에 대응하는 조각으로 나누는 도해.

**무엇을 전달하나**: 텍스트 단위와 모델 입력 단위의 차이.

**우리 교재에서 쓸 장면 예**: “회의록을 요약해”를 검증한 토큰 칩으로 분해.

**기본 파라미터**: 경계 공개 200~300ms, 칩 이동 400~600ms, 시차 30~60ms, 홀드 ≥1800ms; E/S, 칩 간격 8~12px.

**구현 메모**: 실제 tokenizer의 id·조각 데이터를 준비. 원문 위치 칩→칩 레일 좌표로 이동. 실제 디코딩 경계가 문자 경계와 어긋나면 바이트·id 보조 표시. [S10].

**과용 주의·금지**: 글자·음절·단어 하나=토큰 하나로 일반화 금지. 실제 결과가 없으면 설명용 분절 명시. 모델·토크나이저 버전 기록.


### 29. 임베딩 점 이동 · Embedding projection / Point movement

**한 줄 정의**: 토큰·문서를 벡터 표현의 축소 지도에 배치하는 도해.

**무엇을 전달하나**: 표현의 유사성과 검색·분류 관계.

**우리 교재에서 쓸 장면 예**: 유사한 업무 문서 점들이 지도에서 가까운 위치로 정리.

**기본 파라미터**: 800~1200ms, 시차 30~50ms, 홀드 ≥2000ms; S, 점 6~10px, 라벨 간격 ≥16px.

**구현 메모**: 고정 id·사전 좌표·투영 방법을 데이터로 보관. 칩→점 이동은 설명 단계 연결로 표시. [S11].

**과용 주의·금지**: 고차원 벡터가 실제 2D 공간에서 움직인다고 설명 금지. 투영상의 군집 면적·군집 간 거리를 실제 의미 거리로 단정하지 않음.


### 30. 어텐션 선 굵기 · Attention weight encoding

**한 줄 정의**: 선 굵기·농도로 특정 질의 토큰의 가중치를 표현.

**무엇을 전달하나**: 현재 위치에서 다른 위치를 참조하는 정도.

**우리 교재에서 쓸 장면 예**: “그것”이 앞 문장의 어떤 말과 연결되는지 설명.

**기본 파라미터**: 선 공개 400~600ms, 질의 전환 300~500ms, 홀드 ≥1800ms; P, 선 1~6px, 라벨 간격 12~20px.

**구현 메모**: 선 path는 고정, stroke-width·opacity를 사전 가중치에서 계산. 한 layer/head/query 슬라이스를 표시하고 마스크된 미래 연결은 제외. [S9].

**과용 주의·금지**: 선 굵기를 이유·중요도의 확정 증거로 단정 금지. 모든 head를 한 선처럼 합치지 않음. 예시 가중치와 측정값 구분.


### 31. 확률 막대 · Next-token probability bars

**한 줄 정의**: 다음 토큰 후보들의 조건부 확률을 길이로 표시.

**무엇을 전달하나**: 가능한 후속 후보와 선택의 불확실성.

**우리 교재에서 쓸 장면 예**: “오늘 회의는” 뒤 후보 4개와 나머지 표시.

**기본 파라미터**: 500~800ms 분포 공개, 후보 선택 180~250ms, 단계 홀드 ≥1800ms; L/P, 막대 간격 16~24px.

**구현 메모**: 축 0~100% 고정·동일 easing으로 막대와 숫자 동기화. 선택 후보는 별도 테두리 후 다음 생성 라벨로 이동. [S9].

**과용 주의·금지**: logit·확률·사실 신뢰도를 혼용 금지. 상위 후보만이면 나머지 확률 표기. 가장 큰 막대가 언제나 선택된다고 설명 금지.


### 32. 컨텍스트 창 채우기 · Context window fill

**한 줄 정의**: 입력·대화·자료 등 토큰 예산 점유를 채움으로 표시.

**무엇을 전달하나**: 정보가 들어오는 범위와 길이 한계.

**우리 교재에서 쓸 장면 예**: 시스템 지시·질문·문서를 구분해 예산 막대 채우기.

**기본 파라미터**: 구간당 350~600ms, 구간 간 250~400ms, 완료 홀드 ≥2000ms; L/P, 구간 경계 2~4px.

**구현 메모**: 모델별 예산 규칙을 기록하고 입력 항목·예약 출력의 관계를 구분. scaleX 막대·단위 칸과 누적 숫자를 같은 데이터에서 계산.

**과용 주의·금지**: 모든 제품이 자동으로 오래된 대화를 삭제한다고 묘사 금지. 표시 못한 내부 메시지로 실제 점유와 다를 수 있음. 창 크기=장기 기억이라는 설명 금지.


### 33. 자동회귀 생성 루프 · Autoregressive generation loop

**한 줄 정의**: 선택된 토큰을 시퀀스에 붙이고 다음 분포를 갱신하는 반복 도해.

**무엇을 전달하나**: 답 전체를 한 번에 가져오는 과정과의 차이.

**우리 교재에서 쓸 장면 예**: 후보 분포→토큰 선택→문장에 추가를 3회 보여주기.

**기본 파라미터**: 분포 500ms→선택 200ms→추가 350ms→홀드 500~800ms; L/P, 토큰 칩 간격 8~12px.

**구현 메모**: 선택 기록과 각 단계 분포를 배열로 준비. 유한 횟수 타임라인, 종료 토큰·최종 정지 상태 포함. [S9].

**과용 주의·금지**: 영상 반복 속도를 실제 계산 속도로 해석하지 않게 함. 모든 후보를 차례대로 시험한다는 연출 금지. 종료 없는 루프 금지.


## E. 함께 쓰는 설계 용어·개념

### 34. 분절 단위 · Grapheme / Word / Line segmentation

**한 줄 정의**: 문자를 애니메이션 대상 묶음으로 나누는 설계 단위.

**무엇을 전달하나**: 한국어 읽기 단위와 모션 시차의 기준.

**우리 교재에서 쓸 장면 예**: 글자는 제목, 뜻 단위 어구는 자막, 행은 본문 공개.

**기본 파라미터**: 준비 단계 처리, 글자 시차 20~35ms·어구 80~120ms; E/Q, 행 간격 12~20px.

**구현 메모**: Intl.Segmenter grapheme과 검수한 한국어 어구 배열 사용. 폰트 로드 후 줄바꿈 고정. [S4][S7].

**과용 주의·금지**: 공백 분할만으로 한국어 의미 단위가 보장되지 않음. 화면읽기 프로그램에 글자 조각을 각각 읽히지 않음.


### 35. 객체 대응 · Object constancy / Keyed identity

**한 줄 정의**: 변화 전후 같은 대상의 식별자를 유지하는 규칙.

**무엇을 전달하나**: 움직이는 항목이 무엇이었는지 기억.

**우리 교재에서 쓸 장면 예**: 검색 문서 A가 3위에서 1위로 이동.

**기본 파라미터**: 이동 600~800ms, 전후 홀드 ≥1200ms; P, id·색·라벨 고정, 시차 0ms.

**구현 메모**: 데이터 id를 키로 매핑해 라벨·점·막대를 같은 래퍼로 이동. 추가·삭제는 enter/exit 상태 따로 정의. [S6].

**과용 주의·금지**: 배열 인덱스를 객체 id로 쓰지 않음. 값이 바뀌는 과정과 객체가 교체되는 과정을 분리.


### 36. 진행률·스크러빙 · Progress / Scrubbing

**한 줄 정의**: 사용자 스크롤이나 재생 시각을 정규화 진행률로 바꾸는 제어.

**무엇을 전달하나**: 앞뒤 탐색해도 동일한 단계 상태 유지.

**우리 교재에서 쓸 장면 예**: 체험관 슬라이더로 어텐션 단계 되돌리기.

**기본 파라미터**: 영상 t/T, 덱 p 0~1; driver L, scrub 0~600ms 선택, 단계 간 p≈0.2~0.25.

**구현 메모**: 각 시점의 좌표·텍스트·선택 상태를 p에서 재계산. 이벤트 누적 대신 절대 상태 사용. [S5][L3].

**과용 주의·금지**: scrub 0.6은 시차 보정 0.6초이며 장면 길이가 아님. 역방향 탐색에 삭제된 DOM·누적 카운터가 남지 않음.


### 37. 읽기 홀드·발화 큐 · Reading hold / Narration cue

**한 줄 정의**: 완성 화면을 읽을 시간과 발화 시작점을 함께 정하는 설계.

**무엇을 전달하나**: 시각 변화 뒤 의미 이해와 확인.

**우리 교재에서 쓸 장면 예**: 확률 분포 완성 뒤 “확률은 사실 여부가 아냐” 말하기.

**기본 파라미터**: 단순 제목 1000~1600ms, 차트·원리 1800~3000ms 시작값; 홀드 easing 없음, 전후 E/S, 변화 종료 후 150~250ms 여유.

**구현 메모**: tl label로 reveal_end·narration_key·hold_end 지정. 실제 음성 길이에 맞춰 홀드 늘림. [L2][L3].

**과용 주의·금지**: 시간값을 읽기 보장으로 단정하지 않음. 길고 복잡한 문장은 화면 분리. 음성보다 정보가 너무 늦게 등장하지 않음.


### 38. 변화의 정직성 · Faithful data transition

**한 줄 정의**: 애니메이션 중간값과 표시 목적을 구분하는 설계 규칙.

**무엇을 전달하나**: 실측·예시·보간 사이 혼동 방지.

**우리 교재에서 쓸 장면 예**: 두 시점 값 사이 이동은 “전환”, 실제 중간 기록은 별도 점 표시.

**기본 파라미터**: 수치 전환 500~800ms; L/P, 축·단위 고정, 변경점 사이 홀드 ≥1500ms.

**구현 메모**: 원자료 start/end를 불변으로 두고 보간 state를 별도 계산. 최종 라벨은 정확값, 중간 상태는 필요 시 생략. [S6].

**과용 주의·금지**: overshoot·임의 축 변경·선택적 항목 삭제 금지. 연출한 중간 프레임을 실측 시계열처럼 제공하지 않음.


### 39. 모션 축소·정적 대안 · Reduced motion / Static equivalent

**한 줄 정의**: 큰 이동 없이 동일한 정보와 조작 경로를 제공하는 규칙.

**무엇을 전달하나**: 접근성과 멀미 감소·내용 보존.

**우리 교재에서 쓸 장면 예**: 토큰 칩 이동 대신 분절된 원문과 단계 버튼 표시.

**기본 파라미터**: 필수 상태 변경 즉시 또는 100~150ms fade; L, 이동 0px·scale 1, 단계 간격 사용자 제어.

**구현 메모**: prefers-reduced-motion에 맞춰 최종 상태·정적 주석을 표시. 덱 핀 제거·실제 focus 유지, 영상은 정적 장면 중심 별도 버전 검토. [S3][L3].

**과용 주의·금지**: 애니메이션만 끄고 정보까지 숨기지 않음. 카운트업 시작값 0에 멈추지 않음. 필수 정보는 색·모션 하나에만 맡기지 않음.

### 공통 구현 조각

아래는 장면 조립용 예시이며 완성 HyperFrames HTML이 아님. GSAP·CustomEase를 로컬 번들로 준비하고 루트·클립 시간 계약을 별도 적용. E 곡선을 정확히 맞추려면 CSS 문자열을 GSAP `ease`에 그대로 넣지 말고 CustomEase를 등록.

```js
gsap.registerPlugin(CustomEase);
CustomEase.create('eduEntrance', '0,0,0.2,1');
const tl = gsap.timeline({ paused: true });
window.__timelines = window.__timelines || {};
window.__timelines['m3-demo'] = tl;

// 고정 최종 크기의 가로 막대. 기준선은 CSS transform-origin:left.
tl.fromTo('.bar-fill', { scaleX: 0 }, {
  scaleX: 1, duration: 0.7, ease: 'none', stagger: 0.06
}, 0.2);

// 준비 단계에서 고정 경로 길이 계산. 뒤 장면은 초기 숨김을 CSS에 선언.
const path = document.querySelector('#flow-path');
const length = path.getTotalLength();
path.style.strokeDasharray = String(length);
tl.fromTo(path, { strokeDashoffset: length }, {
  strokeDashoffset: 0, duration: 0.8, ease: 'none'
}, 1.4);

// 문자열 상태는 매 seek 시각에서 복원. 이전 실행 결과를 누적하지 않음.
const states = [
  { t: 0, text: '' },
  { t: 0.2, text: '대상:' },
  { t: 0.5, text: '대상: 신입 직원' },
  { t: 1.5, text: '대상: 신입 직원\n형식: 세 문장' }
];
function textAt(t) {
  for (let i = states.length - 1; i >= 0; i--) {
    if (t >= states[i].t) return states[i].text;
  }
  return '';
}
// 입력 장면의 종료 시각까지 타임라인 길이를 명시적으로 확보.
const textClock = { t: 0 };
tl.fromTo(textClock, { t: 0 }, {
  t: 2, duration: 2, ease: 'none'
}, 2.4);

// 기존 공통 타임라인의 onUpdate에 통합. 여러 항목이 callback을 덮어쓰지 않음.
const input = document.querySelector('#prompt-text');
function syncText() {
  input.textContent = textAt(tl.time() - 2.4);
}
tl.eventCallback('onUpdate', syncText);
syncText(); // 초기 프레임도 완전한 상태로 구성
```

이 예시의 입력창은 `white-space:pre-wrap`과 최종 문장에 맞춘 고정 레이아웃 사용. 실제 form input을 재현할 때는 `.value`와 선택 범위도 별도 상태로 관리. `onComplete`에서만 완료 텍스트를 바꾸면 끝 프레임 직접 seek·역방향에서 깨지므로 완료 상태도 시간표에 포함. 렌더러가 콜백을 억제하는 사용자 seek를 호출한다면 그 경로에서 같은 `syncText()`를 명시적으로 호출.

### 제작 검수 기준

완성값·원자료 일치, 단위·분모·축 일치, 0초·중간·끝·역방향 동일 상태, 한글·이모지 분절, 폰트 로드 후 줄바꿈, 자막 영역 충돌, 35% 착지·55% 홀드, 모션 축소 최종 정보 보존을 확인. 막대 비교·확률·예산은 가장 큰 값과 작은 값, 0, 음수, 소수, 항목 추가·삭제 사례도 확인. 예시 코드·권장값은 이번 조사에서 브라우저 렌더·속도 실측을 하지 않았음.

## G. 출처와 로컬 근거

본문 [S번호]는 공개 원출처·공식 구현 문서, [L번호]는 먼저 읽은 로컬 자료. 접근 확인일은 모두 2026-09-30. 아래 URL 확인과 HTTP 본문 조회로 조사했으며 검색 엔진 조회는 DuckDuckGo의 자동 접속 확인 화면, Google의 검색 접근 안내 때문에 검색 결과 본문을 근거로 삼지 못함. Bing도 조회했지만 질의와 무관한 결과가 반환돼 근거에서 제외. 공식 본문·공식 소스 저장소를 직접 확인한 내용과 제한을 구분해 기록.

### 공식 모션·구현 출처

**[S1] Material Design motion**: [Material 3 easing and duration](https://m3.material.io/styles/motion/easing-and-duration/tokens-specs), [Material 2 speed](https://m2.material.io/design/motion/speed.html). 두 페이지는 JavaScript 안내만 응답해서 본문 전체 확인 못함. 곡선·duration 값은 Google의 [Material Web 공식 motion 토큰 v0.192](https://github.com/material-components/material-web/blob/main/tokens/versions/v0_192/_md-sys-motion.scss) 원문으로 확인. legacy·standard·emphasized 곡선, short 50~200ms·medium 250~400ms·long 450~600ms·extra-long 700~1000ms 토큰 제공. 이 사전의 항목별 시간은 이 토큰을 그대로 공식 규격으로 주장하지 않고 교재 시작값으로 제안.

**[S2] IBM Carbon motion**: [Motion 공식 가이드](https://carbondesignsystem.com/elements/motion/overview/). HTML 본문 확인. productive·expressive 모션 구분, standard·entrance·exit 곡선, 과장된 bounce·stretch·sudden stop 회피. 반복 UI 작업·표·데이터 시각화는 productive 모션, 표현적 모션은 중요한 순간에 제한. `/guidelines/motion/overview/`와 `/elements/motion/usage/`는 조사 시 404라 근거 URL에서 제외.

**[S3] Apple HIG motion**: [Motion](https://developer.apple.com/design/human-interface-guidelines/motion). 공개 페이지는 JavaScript 안내, Apple이 제공하는 [같은 문서 JSON](https://developer.apple.com/tutorials/data/design/human-interface-guidelines/motion.json)에서 본문 확인. 목적 있는 모션, 과잉 모션 회피, 모션 선택 가능성, 사용자 제스처와 기대에 맞는 피드백을 근거로 사용. Apple이 모든 UI에 특정 300ms나 단일 cubic-bezier를 강제한다고 주장하지 않음.

**[S4] GSAP text·easing**: [SplitText](https://gsap.com/docs/v3/Plugins/SplitText/), [Easing](https://gsap.com/docs/v3/Eases/), [CustomEase](https://gsap.com/docs/v3/Plugins/CustomEase/). 앞 두 문서 본문 직접 확인. 글자·단어·행 분리, mask, 접근성 라벨, ease 계열 근거. CustomEase URL은 공식 구현 참고 링크이며 이번 조사에서 별도 본문 재조회하지 않음. SplitText의 responsive autoSplit을 영상에서 재생 중 재분절로 쓰지 말고 렌더 레이아웃을 고정.

**[S5] GSAP scroll**: [ScrollTrigger](https://gsap.com/docs/v3/Plugins/ScrollTrigger/). 본문 확인. scrub·pin·snap·timeline 연결 기능 근거. 스크롤 진행률로 영상 시간을 자동 보장한다는 의미가 아님.

**[S6] D3 transition**: [d3-transition](https://d3js.org/d3-transition). 본문 확인. 숫자·색·transform·숫자가 든 문자열 등의 보간, 사용자 정의 tween 제공. HyperFrames에서 보간만 가져오고 시간 제어는 GSAP 한 타임라인에 맡기는 것은 우리 구현 판단.

**[S7] 한글·문자 분절**: [MDN Intl.Segmenter](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Segmenter). 본문 확인. locale별 grapheme·word·sentence 분절 기능 근거. 한국어 수업의 뜻 단위 어구 구분은 별도 검수 필요.

### 원전·원리·편집 출처

**[S8] Disney 12원칙 원전**: Frank Thomas·Ollie Johnston, *The Illusion of Life: Disney Animation*, 최초 출간 1981로 알려진 원전이며 이번 직접 확인은 아래 재판 소개 범위. [Disney Books 공식 소개](https://books.disney.com/book/the-illusion-of-life/)에서 저자·서명·애니메이션 제작 경험과 1995-10-19 재판 발매 표시 확인. 이번 조사에서는 책 전체·12원칙 해당 장 원문을 열람하지 않았으므로 원전 문장이나 파라미터를 인용하지 않음. staging·timing·slow in/out·overlapping action 등은 이 문서에서 읽기 초점·시차·이징을 설계할 때 연결하는 배경 개념. 데이터 길이 자체를 squash/stretch하거나 값에 overshoot를 주는 근거로 사용하지 않음.

**[S9] 트랜스포머 원논문**: [Attention Is All You Need](https://arxiv.org/abs/1706.03762), Vaswani 외, 2017. arXiv 서지·초록 확인. 토큰 임베딩·어텐션·출력 확률·자동회귀 설명의 원전 연결 링크이며 이번 모션 조사에서는 논문 전체 계산을 재현하지 않음. 교재 선·막대의 가상 수치가 논문 실측값이라는 뜻이 아님.

**[S10] 토큰 분절 구현**: [OpenAI tiktoken](https://github.com/openai/tiktoken), [공식 README](https://raw.githubusercontent.com/openai/tiktoken/main/README.md). 모델별 encoding 선택과 BPE 구현 참고. [OpenAI Tokenizer](https://platform.openai.com/tokenizer)는 이번 접속이 403이라 실제 예시 분절값 확인에 사용하지 않음. 교재 문장을 해당 tokenizer로 실행한 결과는 별도 제작 시 확보.

**[S11] 투영 도해의 해석 한계**: [How to Use t-SNE Effectively](https://distill.pub/2016/misread-tsne/), Wattenberg·Viégas·Johnson, 2016-10-13. 본문 확인. 투영의 perplexity·안정화·군집 크기·거리 해석 문제를 확인. 모든 임베딩 도해가 t-SNE라는 뜻이 아니라 축소 지도 비유에서 과장 해석을 막는 근거.

**[S12] 영화 편집 용어 연결**: [Adobe Match cut](https://www.adobe.com/creativecloud/video/post-production/cuts-in-film/match-cut.html). 본문 확인. 이전·다음 장면의 시각·청각 유사성을 통해 연결하는 컷. UI 확대→원리 도해에서 같은 칩·도형을 유지하는 연결에 참고. 한 도형이 연속 변화하는 morph와 장면을 자르는 match cut은 구분. Adobe 설명은 현대 편집 실무의 공식 해설이며 최초 역사적 원전은 아님.
