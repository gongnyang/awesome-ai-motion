# 2 전환·컷·카메라

확인일: 2026년 9월 30일. 대상: 3~5분 한국어 설명 영상, 화면 입력 시연, 원리 도해, 스크롤덱·체험관. 작성: M2.

## 읽는 기준

**컷은 무엇을 이어 붙이는지, 전환은 어떻게 넘기는지, 카메라는 어디를 보게 하는지, 장면 구조는 언제 이해시키는지 정하는 말이야.** 같은 구현도 목적에 따라 이름이 달라져. 하드 컷은 교체 방식이고 스매시 컷은 그 교체가 만드는 강한 대비야. 인서트·컷어웨이는 삽입하는 숏의 역할이고, 크로스페이드는 두 화면을 섞는 전환이야.

각 항목의 시간·거리·홀드·빈도는 **우리 교재용 시작값**이야. 공식 원전의 보편 규칙이나 검증된 학습 효과 수치로 읽지 마. 정보 전달 효과는 설계 의도이며 실제 이해도는 시청·조작 점검으로 확인해. 1920×1080·30fps 기준으로 1프레임은 약 33.33ms야. 0ms 컷은 한 프레임 경계에서 즉시 교체한다는 뜻이고, 그 항목의 이징은 적용 안 함이야. GSAP `duration`과 HyperFrames `data-start`·`data-duration`은 초 단위라서 ms를 1000으로 나눠 써.

## 공통 이징·구현 계약

| 표기 | 곡선·값 | 적용 |
| :--- | :--- | :--- |
| LIN | `none` / CSS `linear` / `cubic-bezier(0, 0, 1, 1)` | 일정한 카메라 이동·스크롤 진행·불투명도 혼합 |
| STD | Carbon standard productive / `cubic-bezier(0.2, 0, 0.38, 0.9)` | A에서 B로 위치가 바뀌는 연속 이동 |
| ENT | Carbon entrance productive / `cubic-bezier(0, 0, 0.38, 0.9)` | 빠르게 나타나고 멈추는 리빌 |
| EXP | Carbon standard expressive / `cubic-bezier(0.4, 0.14, 0.3, 1)` | 소수의 중요한 개념 전환 |
| SOFT | 교재용 부드러운 대칭 곡선 / `cubic-bezier(0.42, 0, 0.58, 1)` | 긴 카메라 이동·초점 이동 |

Carbon 곡선·70/110/150/240/400/700ms 토큰은 [S1]에서 확인했어. 아래 항목의 300~600ms 등은 우리 제작 제안이야. `power2.inOut`·`sine.inOut`은 위 cubic-bezier와 동일한 함수가 아니야. 정확히 맞추려면 CustomEase를 로드·등록하고 `CustomEase.create('m2Std', '0.2,0,0.38,0.9')`처럼 써. CSS에만 cubic-bezier 문자열을 바로 넣어. GSAP 기본 `ease`에 CSS 문자열을 그대로 넘기지 마 [S10].

HyperFrames는 composition마다 `gsap.timeline({paused:true})` 하나를 만들고 root의 `data-composition-id`와 같은 키로 `window.__timelines[id]`에 등록해. 타임라인·미디어 길이를 root `data-duration` 안에 넣어. 화면 이동은 `.clip`의 내부 `.visual`·`.camera`에 걸고, 미디어 재생·시킹은 프레임워크에 맡겨. `onComplete`에서 DOM을 교체하거나 `setTimeout`으로 다음 장면을 띄우지 마. 시작·종료 상태는 `fromTo`와 명시적 시점의 `tl.set`으로 만들고 역방향 시킹에도 복원되게 해 [L1·L2].

두 장면을 겹치는 전환은 A의 마지막과 B의 시작에 필요한 시간 창을 확보해. A가 먼저 사라져 빈 화면이 된 뒤 B가 들어오게 하지 마. 배경은 불투명하게 두고 자막은 전환 레이어 밖에 놓아. `.clip`의 `visibility`·`display`·`autoAlpha`는 직접 바꾸지 마. 단순 마스크·블러는 내부 노드에만 걸어. 스크롤덱의 `enter/hold/exit` 문법을 HyperFrames 장면마다 별도의 퇴장 애니메이션을 강제하는 규칙으로 옮기지 마 [L1·L3].

스크롤덱에서는 시간을 진행률 `p=0…1`로 바꿔. 기본 분배는 enter 0.00~0.30, hold 0.30~0.75, exit 0.75~1.00이야. 실제 머무는 ms는 스크롤 속도에 따라 달라져. scrub에 묶인 이동은 LIN부터 쓰고, easing은 시간 재생과 별도로 판단해. 체험관은 선택·정답 확인처럼 행동 뒤에 150~400ms 전환을 붙이고 읽기 단계는 사용자가 다음으로 진행하게 해. `prefers-reduced-motion`이면 큰 이동·줌·휩팬·시차를 제거하고 즉시 교체 또는 100~150ms 불투명도 변화로 대체해. 최종 설명·전후 라벨·다음 버튼은 반드시 남겨 [S2·L3].

## G. 제작 적용 예

입력 시연은 설정 숏 1200ms → 입력 영역 줌 450ms → 읽기 홀드 2500ms → 실제 클릭·응답 → 대기 생략 점프컷 0ms → 결과 홀드 2000ms → 원문 확인 컷어웨이 2000ms 순서로 시작해. 입력 행동·읽기 시간은 실제 자료와 음성에 맞춰 늘려. 줌의 부드러움보다 클릭·결과·검증의 인과가 먼저야.

원리 설명은 질문 비트 → 조건 카드 리빌 350ms → 홀드 1500ms → 도해로 매치컷 0ms → 단계 리빌 간격 200ms → 완성 상태 홀드 2000ms → 실제 입력 예시로 J 컷, 음성 선행 500ms → 마지막 질문 콜백 순서로 시작해. 이 시간표는 완성 대본의 총 길이가 아니라 부분 연출의 시작값이야.

스크롤덱은 의미가 같은 A/B 비교에 `wipe-transform`, 읽기 구간에 hold, 두 pinned 장면 사이의 숨 고르기에 `parallax-video`를 대응시켜. 해당 로컬 템플릿의 loop·play 호출과 tl.call 기반 문구 변경은 웹 덱 구현이야. HyperFrames로 옮길 때는 미디어 재생을 맡기고 문구도 양쪽 상태의 DOM을 미리 만든 뒤 명시적 시각의 opacity로 교체해. 템플릿의 코드를 통째로 복사하면 결정적 시킹 계약과 충돌할 수 있어.
