# 1 애니메이션 원칙과 모션 기본기

작성·확인: 2026-09-30 · 조사 워커 M1 · 대상: 3~5분 강의 영상, 스크롤덱, 체험관

## 사용 기준

목적: 움직임으로 입력·처리·출력, 포함 관계, 순서, 원인·결과를 읽게 해. 밝은 바탕·큰 글자·정돈된 도해를 기본으로 잡고, 내레이션이 설명하는 대상에 움직임을 배정해.

표 읽기: 모든 사전 항목은 **이름 / 정의 / 전달 효과 / 교재 장면 / 기본 파라미터 / 구현 / 과용 주의·금지** 순서야. 시간·거리·크기 범위는 별도 표시가 없으면 **우리 제작용 시작값 제안**이야. 공식 수치는 2절에 따로 적었어. Disney 원칙 자체에는 웹 애니메이션용 ms나 CSS 곡선이 없어.

단위: 문서 시간은 ms, GSAP `duration`·`stagger`·타임라인 위치는 초야. 300ms는 `0.3`. 거리 제안은 1920×1080 도해 기준 px야. 작은 화면에서는 비례 조정하고 실제 글자 가독성으로 판단해. 이징이 해당하지 않는 구성·정지 상태는 `없음`으로 적었어.

범위: 디즈니 12원칙, CSS 표준 이징, GSAP 코어의 모든 이징 계열과 추가 이징, 물리 스프링, 시간·공간·위계·시선·2D 속성 기본기를 다뤄. 임의 사용자 곡선은 무한하므로 ‘전부’는 표준·라이브러리 계열과 확장 방법까지라는 뜻이야. 영화 편집·전환·텍스트 효과의 전체 목록은 M1 범위 밖이야. 여기서는 연속성 설계에 필요한 개념만 연결해.

출처 표기: `[S번호]`는 문서 끝의 원출처 URL, `[L번호]`는 먼저 읽은 로컬 자료야. 웹 검색은 원전·공식 문서를 찾는 용도로 썼고, 수치 근거는 접속한 공식 본문이나 공식 코드로 확정했어. 원전 전체를 읽었다고 주장하지 않아.

## 1. 먼저 고를 기본 모션 언어

기본 세트: 보조 정보 `power2.out`, 주요 등장 `power3.out`, 차분한 장면 내부 이동 `sine.inOut`, 기계적 진행·스크럽 `none`. 같은 기능에는 같은 곡선·방향·강도를 써. 로컬 HyperFrames의 기본 등장 곡선은 `power3.out`이지만 GSAP 라이브러리 자체 기본값은 `power1.out`이야. 혼동하지 마. [L1][S7]

영상 시작값: 작은 피드백 100~180ms, 보조 등장 200~350ms, 주요 도해 등장 350~600ms, 장면 내부 재배치 300~500ms, 읽기 홀드 1500~4000ms. 홀드는 정보량·실제 발화에 맞춰 늘려. 3~5분 내내 계속 움직이지 말고 설명 대상이 정착한 프레임을 남겨.

체험관 시작값: 조작 피드백 70~150ms, 패널 200~300ms, 화면 재구성 300~400ms. 클릭 후 반응은 곧바로 시작하고 다음 입력을 막지 마. 실제 제품 응답 시간이 길면 애니메이션을 늘리지 말고 별도 진행 상태를 보여 줘. [S4][S6]

스크롤덱 기준: 이 저장소는 장면 타임라인 전체를 **0~1 진행도**로 작성해. `enter 0~0.30`, `hold 0.30~0.75`, `exit 0.75~1.00`, 키보드 도착 지점은 `0.35`. `duration:0.12`를 ‘120ms’라고 읽지 마. 스크롤 속도에 따라 실제 시간이 달라져. `scrub:0.6`은 추종 완충의 초 단위 설정이며 장면 자체 길이가 아니야. [L2]

## 2. 공식 지속 시간·이징 기준 수치

### 2.1 Material 레거시와 M3를 구분해

Material 1의 보존 문서는 아래 장치별 기준을 직접 제시해. 유지보수 종료 문서라는 점을 함께 기록해. M2 속도 페이지는 접속했지만 JS 로딩 안내만 받아서 아래 수치를 M2 본문에서 재검증한 값으로 쓰지 않아. [S2]

|---|---|---|
| 모바일 일반 전환 | 대체로 300ms | 짧은 화면 재배치 시작값으로 참고해 |
| 모바일 크고 복잡한 전체 화면 전환 | 375ms | 도해 구조가 많이 바뀔 때 참고해 |

| 태블릿 | 모바일보다 약 30% 길게, 300→390ms 예 | 거리·면적 변화가 커졌을 때 참고해 |

### 2.2 IBM Carbon

Carbon은 생산적 모션(productive)과 표현적 모션(expressive)을 나눠. 표현적 움직임은 드문 중요 순간에 배정하고 바운스·늘어남·갑작스러운 정지는 피하라고 명시해. Disney 원칙을 모두 일반 UI에 그대로 적용하라는 뜻이 아니야. 거리·면적이 커지면 더 긴 시간을 쓰며 아래 6개는 정적 토큰이야. [S4]

| Carbon 지속 시간 토큰 | 원문 값 | 원문 용도 |
|---|---|---|
| `duration-fast-01` | 70ms | 버튼·토글 마이크로 인터랙션 |
| `duration-fast-02` | 110ms | 페이드 같은 마이크로 인터랙션 |
| `duration-moderate-01` | 150ms | 작은 확장·짧은 이동 |
| `duration-moderate-02` | 240ms | 확장·시스템 안내·토스트 |
| `duration-slow-01` | 400ms | 큰 확장·중요 시스템 알림 |
| `duration-slow-02` | 700ms | 배경 디밍 |

| Carbon 곡선 역할 | Productive | Expressive |
|---|---|---|
| Standard, 처음부터 끝까지 보이는 대상 | `cubic-bezier(0.2,0,0.38,0.9)` | `cubic-bezier(0.4,0.14,0.3,1)` |
| Entrance, 등장·사용자 입력에 반응 | `cubic-bezier(0,0,0.38,0.9)` | `cubic-bezier(0,0,0.3,1)` |
| Exit, 사라지는 대상 | `cubic-bezier(0.2,0,1,0.9)` | `cubic-bezier(0.4,0.14,1,1)` |

Carbon 추가 기준: 마이크로 인터랙션 평가 항목은 90~120ms, 표 행 등장 예시는 20ms 스태거, 전체 등장 시퀀스는 500ms 안에 끝나도록 요소 수에 맞춰 간격을 조정해. 70ms 토큰과 90~120ms 평가지침은 서로 다른 항목이니 하나로 합치지 마. [S4][S5]

Apple HIG는 짧고 정확한 피드백, 제스처·공간 기대와 일치하는 이동, 반복 조작의 불필요한 모션 축소, 취소 가능한 움직임을 권장해. 확인한 HIG Motion 본문은 보편적인 ‘모든 UI는 250ms’ 같은 숫자를 주지 않아. 아래 사전의 Apple 관련 ms는 우리 제안이야. [S6]

## 3. 디즈니 12원칙 전체

원전: Frank Thomas·Ollie Johnston, *The Illusion of Life: Disney Animation*, 초판 1981, 3장 “The Principles of Animation”, pp.47~69. 공식 출판사 페이지는 1995 판본을 안내하므로 1995를 원칙의 최초 발표 연도로 쓰지 마. 온라인 요약은 원전의 전체 본문이 아니야. 아래 교재 예·파라미터는 원칙을 정보 도해로 옮긴 설계 제안이야. [S1]

| 이름(한국어 · 영어) | 한 줄 정의 | 무엇을 전달하나 | 우리 교재 장면 예 | 기본 파라미터 | 구현 메모 | 과용 주의·금지 |
|---|---|---|---|---|---|---|
| 01 찌그러뜨리기와 늘이기 · Squash and Stretch | 압축·신장으로 무게·탄성·충격을 표현해 | 재료의 부드러움과 힘의 방향 | 종이 자료 묶음이 수집함에 닿으며 한 번 눌려 | 압축 80~120ms, 복원 180~260ms; `power2.out`; `scaleY:0.94`, `scaleX:1/0.94`; 후속 간격 0ms | 바깥 도형에 `scaleX/scaleY`, 기준점은 바닥. 평면 면적 보존은 곱을 약 1로, 3D 체적 보존과는 구분해 | 본문 글자·실제 UI·막대그래프 수치를 찌그러뜨리지 마. 읽기 전에 정상 크기로 복원해 |
| 02 예비동작 · Anticipation | 본동작 전에 작은 준비 움직임으로 다음 행동을 예고해 | 원인과 방향, 곧 바뀔 위치 | 자료 카드가 목적지 쪽으로 움직이기 전 4px 반대로 당겨져 | 준비 80~140ms, 본동작 250~400ms; 준비 `power1.in`, 본동작 `power3.out`; 역방향 3~6px; 간격 0~40ms | 같은 타임라인에 작은 역이동과 본이동을 순서대로 넣어 | 클릭 피드백을 예비동작 때문에 늦추지 마. 모든 등장에 역동작을 붙이지 마 |
| 03 명료한 연출 · Staging | 구도·대비·동작을 정돈해 한 가지 의미를 분명히 보여 줘 | 지금 봐야 할 대상과 설명의 중심 | 프롬프트 조건 한 줄만 강조하고 나머지는 옅게 남겨 | 강조 150~250ms `power2.out`; 주변 강조 해제 100~180ms; 홀드 1500~3000ms; 동시 초점 1개 | 위치·색 대비를 먼저 설계하고 움직임은 중심 대상에만 줘 | 배경·커서·자막·도해가 동시에 경쟁하지 않게 해. 축소된 주변 텍스트를 필수 읽기 대상으로 삼지 마 |
| 04 순차 작화와 핵심 자세 작화 · Straight Ahead Action and Pose to Pose | 앞 프레임부터 전개하거나 핵심 자세부터 정한 뒤 중간을 연결해 | 즉흥적인 흐름 또는 정확한 상태 변화 | 입력 전·자료 연결·결과 확정의 세 상태를 먼저 그려 | 키 상태 3개; 연결 250~450ms `power3.inOut`; 상태 홀드 800~1800ms | 설명 도해는 pose-to-pose로 좌표·상태를 확정해. 입자도 초기값을 고정한 시간 함수로 계산해 | 순차 작화와 실시간 비결정적 시뮬레이션을 동일시하지 마. 결과 도해의 비율을 중간마다 바꾸지 마 |
| 05 팔로스루와 겹침 동작 · Follow Through and Overlapping Action | 주동체 뒤에 부속이 따라오고 각 부분이 다른 시점에 멈춰 | 관성, 연결된 부분의 유연함 | 자료 묶음 본체가 멈춘 뒤 모서리 탭이 작게 정착해 | 본체 300ms, 부속 시작 지연 40~80ms, 부속 350~450ms; `power3.out`; 진폭 2~5px | 본체·부속을 별도 래퍼로 두고 후행 트윈을 겹쳐. 원칙 1개 안에 두 개념이 들어 있어 | 무관한 목록의 시차 등장을 이 원칙 자체라고 부르지 마. 표·문장마다 흔들리는 꼬리를 붙이지 마 |
| 06 느린 시작과 느린 끝 · Slow In and Slow Out | 시작·끝의 변화량을 작게 해 가속·감속을 보여 줘 | 무게감, 도착과 정착 | 도해 묶음이 화면 안에서 다른 칸으로 이동해 | 300~450ms; `sine.inOut` 또는 Material legacy standard `(0.4,0,0.2,1)`; 간격 0ms | 같은 시간 간격의 위치 샘플이 양 끝에서 촘촘해지게 이징을 적용해 | 선형이어야 할 진행률·시간 축에 장식적 가감속을 넣지 마. 전통 작화의 slow-in/out 명명과 API 이름을 기계적으로 일대일 대응하지 마 |

## 4. 이징 사전

### 4.1 곡선의 읽는 법

이징은 정규화 시간 `p∈[0,1]`를 정규화 변화량 `E(p)`로 바꾸는 함수야. 같은 경로·동작 시간이어도 초반과 후반의 이동량이 달라져. 곡선 기울기는 속도 비율이고, 가파르면 한 프레임에서 더 많이 변해. 이징 그래프와 화면에서 이동하는 공간 경로는 서로 달라.

CSS `cubic-bezier(x1,y1,x2,y2)`는 시간·진행률 그래프의 제어점이야. x1·x2는 0~1 안이어야 하고 y는 밖으로 나갈 수 있어. 아래의 `≈`는 널리 쓰는 **근사 프리셋**이며 GSAP의 수학 함수와 완전히 같지 않아. 표에서 ‘in / out / inOut’ 순서로 적힌 값은 해당 변형의 순서야. 공식 CSS 키워드는 정확한 값, 물리·다중 반동은 단일 cubic-bezier로 정확히 표현할 수 없어. [S7][S8]

### 4.2 스프링 물리 파라미터를 바로 조정하는 법

계산 모델: 목적지가 1인 정규화 위치를 `x(t)`라 할 때 `m·x'' + c·x' + k·(x−1)=0`. `m`은 질량, `k`는 강성, `c`는 감쇠 계수, `v0=x'(0)`는 초기 속도야. 임의 UI 단위를 쓰면 아래 값은 해당 정규화 모델에만 맞아. 프레임률과 독립된 시간 t의 함수로 계산해. Apple SwiftUI의 실제 Spring API도 mass·stiffness·damping을 입력받아. 여기의 계산 예를 Apple 권장 기본값으로 제시하는 건 아니야. [S12]

| 이름(한국어 · 영어) | 한 줄 정의 | 무엇을 전달하나 | 우리 교재 장면 예 | 기본 파라미터 | 구현 메모 | 과용 주의·금지 |
|---|---|---|---|---|---|---|
| 질량 · Mass m | 같은 힘에서 얼마나 덜 가속하는지 정해 | 무거움·가벼움 | 자료 한 장과 묶음의 정착 차이 | 기준 `m=1`, 비교 `m=2`; 곡선 spring; 시간은 계산; 간격 0ms | m을 바꾸면 `ωn=√(k/m)`, `ζ=c/(2√(km))`도 다시 계산해 | 질량만 늘리면 감쇠비도 달라져. ‘무게만 바뀐다’고 쓰지 마 |
| 강성 · Stiffness k | 목표로 되돌리는 힘의 세기를 정해 | 빠른 복귀·단단한 결합 | 칸에 놓인 조각의 빠른 정착 | 기준 `k=400`; 빠르게는 625, c는 원하는 ζ에 맞춰 재설정; 시간은 계산 | `c=2ζ√(km)`로 감쇠비를 유지해 | k와 duration을 동시에 무작정 줄이면 물리 의미를 잃어 |
| 감쇠 · Damping c | 속도에 비례해 에너지를 줄여 | 잔진동이 얼마나 남는지 | 도착 뒤 즉시 읽기 가능한 패널 | `m=1,k=400,c=40`; 임계감쇠; 간격 0ms | c를 바꾸고 ζ·정착시간을 같이 기록해 | 감쇠 계수 c와 감쇠비 ζ를 같은 단위로 적지 마 |
| 감쇠비 · Damping ratio ζ | 실제 감쇠를 임계감쇠에 대한 비율로 나타내 | 진동·비진동 성격 | 주요 패널은 비진동, 놀이 조각만 약한 반동 | `ζ=1` 기본; `0.8~0.9` 약한 반동; `0.6~0.7` 놀이 한정; 시간은 계산 | `ζ<1` 저감쇠, `=1` 임계, `>1` 과감쇠. 영초기속도 표준 모델에서 ζ=.8의 최대 초과 약 1.52%, .85는 약 .63% | 이 값을 ‘Apple/iOS 기본값’이라고 단정하지 마. HIG 본문에는 그 수치가 없어 |
| 초기 속도 · Initial velocity v0 | 시작할 때 이미 가진 속도를 지정해 | 손짓·드래그에서 자연스러운 인계 | 체험관 드래그를 놓은 조각이 이어서 움직여 | 영상 `v0=0`; 체험관은 측정 px/s를 목표 거리로 나눠 정규화; 간격 0ms | 목표까지 거리·좌표 단위와 velocity 단위를 맞춰. 목표 거리가 0이면 별도 처리해 | 고정 영상에 임의 입력 속도를 주지 마. 같은 값이라도 라이브러리마다 단위가 달라 |

| 정착 임계값 · Rest threshold / epsilon | 목표·속도에서 충분히 작아진 오차를 정지 기준으로 정해 | 정확한 도착과 잔여 꼬리 제거 | 결과 프레임이 완성돼 | 정규화 위치 `ε=0.001`; 실시간 UI는 속도 임계도 지정; 시간 계산; 간격 0ms | 모든 후속 시간에 오차가 임계 안인지 확인해. 렌더 곡선 끝점을 정확히 1로 보정해 | 첫 번째 목표 통과 시점에서 멈추면 저감쇠 반동을 잘라 버려 |

임계감쇠·정지 출발의 seek-safe 예: `m=1,k=400,c=40`이면 `ωn=20rad/s`, 위치 `x(t)=1−(1+20t)e^(−20t)`. `T=0.462s`에서 위치 오차는 약 0.1%야. 아래 함수는 상태를 누적하지 않아서 앞뒤로 탐색해도 같은 프레임이 나와. 끝점 보정은 유한 구간 렌더용 조정이며 원래 무한시간 물리 해와 미세하게 달라.

```js
const T = 0.462;
const springPosition = t => 1 - (1 + 20 * t) * Math.exp(-20 * t);
const endCorrection = 1 - springPosition(T);
const criticalSpring = p => springPosition(p * T) + p * endCorrection;
tl.fromTo('.panelMotion', { y: 24 }, {
  y: 0, duration: T, ease: criticalSpring, immediateRender: false
}, 0.2);
tl.fromTo('.panelMotion', { opacity: 0 }, {
  opacity: 1, duration: 0.16, ease: 'power2.out', immediateRender: false
}, 0.2);
```

저감쇠·영초기속도일 때는 `ωd=ωn√(1−ζ²)`, `x(t)=1−e^(−ζωn t)[cos(ωd t)+(ζωn/ωd)sin(ωd t)]`로 계산할 수 있어. 초기 속도가 0이 아니거나 과감쇠면 맞는 해를 따로 써. 저감쇠 최대 오버슈트의 비율은 `exp(−πζ/√(1−ζ²))`야. 위치·시간·오차를 고정 샘플링해 베이크하면 GSAP·CSS `linear()`로도 옮길 수 있어.

## 9. GSAP·CSS·HyperFrames 적용 계약

### 9.1 공통 변환 계약

이징 숫자는 CSS와 GSAP에서 같은 것으로 자동 번역되지 않아. 정확한 공식 곡선을 쓰려면 `CustomEase`를 별도 로드·등록하고 네 숫자로 생성해. 실용적으로 비슷한 움직임이면 `power3.out` 같은 코어 이름을 쓰고 ‘공식 곡선의 근사’라고 적어.

```js
// GSAP·CustomEase 로드가 끝난 setup에서 실행해.
gsap.registerPlugin(CustomEase);
CustomEase.create('carbonEnter', '0,0,0.38,0.9');
CustomEase.create('materialLegacy', '0.4,0,0.2,1');
const tl = gsap.timeline({ paused: true, defaults: { ease: 'power3.out' } });
tl.fromTo('.cardMotion', { y: 16, opacity: 0 }, {
  y: 0, opacity: 1, duration: 0.24,
  ease: 'carbonEnter', immediateRender: false,
  stagger: { each: 0.03, from: 'start' }
}, 0.2);
```

위 코드는 단순 내부 등장 예야. 실제 구성에서는 DOM 시작 상태를 CSS로 명시해. later-scene의 `fromTo`는 `immediateRender:false`와 명시한 시작값으로 미래 장면의 초기값이 앞 시간에 적용되지 않도록 해. 시작·중간·역탐색에서도 맞는지 확인해. DOM에 직접 `from()`을 걸어 뜻밖에 숨기는 패턴은 피해야 해. [L1][L2]

CSS 사용 예: 체험관의 짧은 버튼 피드백에는 `transition: transform 110ms cubic-bezier(0,0,0.38,0.9)`를 쓸 수 있어. 영상의 CSS animation은 벽시계에 따라 자동 재생하지 말고 HyperFrames CSS 어댑터의 seek 등록 규약으로 연결해. 그냥 CSS transition을 썼다는 것만으로 임의 시점 탐색이 가능해지는 건 아니야.

### 9.2 HyperFrames 결정성

composition마다 paused GSAP 타임라인을 하나 등록해. 등록 키는 루트 `data-composition-id`와 같게 해. 영상 길이는 명시한 루트 `data-duration`으로 관리하고, 타임라인이 그보다 길면 잘린다는 점을 기억해. 이 절은 실행 프로젝트가 아니라 제작 계약 예야. [L1][L3]

```js
// 루트에 data-composition-id="lessonMotion", data-duration="5"를 선언한 경우
const tl = gsap.timeline({ paused: true, defaults: { ease: 'power3.out' } });
tl.addLabel('input', 0.2);
tl.fromTo('.inputMotion', { y: 16, opacity: 0 }, {
  y: 0, opacity: 1, duration: 0.3, immediateRender: false
}, 'input');
tl.addLabel('result', 1.4);
tl.fromTo('.resultMotion', { x: 24, opacity: 0 }, {
  x: 0, opacity: 1, duration: 0.35, immediateRender: false
}, 'result');
// 1.75초 뒤부터 5초까지 완성 프레임을 읽게 해.
window.__timelines['lessonMotion'] = tl;
```

좌표·DOM 치수는 setup에서 한 번 확정해. 렌더 시점마다 `getBoundingClientRect()`로 경로를 바꾸지 마. 공간 이동은 x·y·scale·rotation을 쓰고 width·height·top·left의 레이아웃 트윈은 피해야 해. 필요한 표·텍스트 재배치는 미리 정한 좌표나 래퍼 변환으로 처리해.

클립의 생명주기는 프레임워크가 관리해. `.clip`에 autoAlpha·visibility·display 트윈을 걸지 말고 내부 래퍼의 opacity·transform을 바꿔. 실시간 `setTimeout/setInterval`, 무한 repeat, `Date.now/Math.random`로 장면을 움직이지 마. 반복 횟수·난수 초기값·곡선·시간을 고정해. [L1][L3]

로컬 자료 차이: 요청 경로의 애니메이션 스킬은 async 타임라인 구성에 엄격하고, 현재 core는 `document.fonts.ready` 안에서 완료 후 등록하는 방식도 지원한다고 적어. 이번 사전 기본 패턴은 글꼴·자산 준비가 끝난 setup에서 동기 구성·등록으로 잡았어. 실제 제작 버전의 core·lint 계약을 우선해. [L1][L3]

### 9.3 덱과 영상의 수치를 변환할 때

장면의 영상 길이를 `D초`, 덱의 위치를 `p`, 진행도 기간을 `d`라 정했다면 대응 초안은 `t=p×D`, `duration=d×D`야. 이 환산은 **고정 영상 초안**에만 유효해. 예를 들어 `.12` 구간과 D=5초면 영상 600ms야. 실제 스크롤에서는 `.12`가 600ms라는 보장이 없어.

덱에서는 키보드 진입 .35에 제목·핵심 도해가 이미 보이고 역스크롤해도 관계가 유지돼야 해. 체험관에서는 빠른 반복 클릭·취소에 현재 상태에서 반응해야 해. 영상에서는 내레이션의 실제 의미 지점과 시간을 맞춰야 해. 같은 사전 항목이라도 세 환경의 재생 계약을 나눠 적용해.

## 10. 즉시 적용할 시작 레시피

### 10.1 프롬프트 입력에서 조건 도해로

정지 입력 화면 확보 → 조건 줄 강조 180ms `power2.out` → 해당 문장과 같은 색의 도해 카드 등장 300ms `power3.out` → 연결선 350ms `none` → 결과 라벨 200ms `power2.out` → 2500ms 홀드.

전달 의미: 입력의 어느 문장이 도해의 어느 조건인지 이어져. 실제 서비스 화면과 교육용 재현·원리 비유를 표시해. 임의 연출 시간을 실제 추론 속도처럼 보여 주지 마. [L4]

### 10.2 입력·자료·결과의 단계 설명

틀·제목은 먼저 정지 배치 → 카드 3개 등장 240ms, stagger 50ms, `power3.out` → 첫 연결선 300ms → 다음 단계는 내레이션 지점에 맞춰 초점 이전 180ms → 마지막 결과에 한 번 테두리 강조 150ms → 3000ms 홀드.

전달 의미: 데이터의 소속·흐름을 순서대로 읽어. 한 그룹 등장 총시간은 `240+2×50=340ms`. 중요한 내용이 마지막에 정착하되 초기 구조·제목은 이미 보여.

### 10.3 스크롤덱의 구조 분해

진행도 0~.30: 구성 요소 등장 → .30~.75: 완성 도해를 남기고 강조만 순서대로 이동 → .75~.98: 묶음으로 퇴장. 키보드 도착 .35에서 구조 전체가 보이게 해. 설명 요소는 `anatomy-rows` 템플릿의 기존 계약을 참고해. [L2]

전달 의미: 사용자가 멈추면 읽을 수 있고, 역스크롤하면 같은 구조가 복원돼. 글자의 움직임보다 선·강조의 변화로 분해 순서를 보여 줘.

### 10.4 체험관의 선택 피드백

클릭 즉시 버튼 반응 110ms Carbon entrance productive → 선택 조각 이동 240ms `power3.out` → 완료가 확인되면 상태 텍스트 교체 150ms → 다음 조작 허용. 모션 감소 설정에서는 이동 없이 선택 테두리·텍스트 상태로 같은 의미를 전달해.

전달 의미: 내가 무엇을 선택했는지, 어디에 놓였는지 확인돼. 드래그 놓기 같은 동작에 한해서 측정 속도를 spring 초기 속도로 넘길 수 있어. 놀이가 목적인 장면만 약한 반동을 추가해.
